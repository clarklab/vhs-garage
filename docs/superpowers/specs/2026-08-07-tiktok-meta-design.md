# Tape Trivia: better TikTok meta

Date: 2026-08-07
Status: approved design, ready to plan

## The problem

Every Tape Trivia post ships identical meta. `defaultPostFields('trivia', name)` in
`public/scripts/tik/project.js` writes a two-sentence template body and the same five
hashtags — `#movietrivia #moviefacts #behindthescenes #movietok #moviequotes` — for
every film we have ever posted.

Three consequences:

1. **We never appear in the searches most likely to find us.** A post about *The Thing*
   carries no `#thething` and no `#johncarpenter`. Those are the highest-intent queries
   that could ever land on our content, and we are not in them.
2. **We cannot learn anything.** Because the tag set never varies, our post history
   contains zero signal about which tags work. Ten posts, one experiment, n=10.
3. **The body reads generic.** It names no year, no director, no cast — nothing that
   makes the post look researched to a human, and nothing for TikTok to index.

## What is and is not possible (verified 2026-08-07)

**Hashtag volume data is not available to us.** TikTok's Creative Center hashtag
endpoint returns `{"code":40101,"msg":"no permission"}` without an ads login, and
`tiktok.com/tag/<tag>` serves a gated shell containing no counts. We cannot fetch
"how big is #movietok". Any such number in this system would be fabricated. The only
volume data we can honestly act on is our own post performance.

**Music cannot be set through the API, under any mode.** `post_info.auto_add_music`
exists but the Content Posting API reference marks it DIRECT_POST-only, and there is
no field for naming a specific track in either mode. We publish with
`post_mode: 'MEDIA_UPLOAD'` (draft-to-inbox) because the app is unaudited. Even after
an audit, the most the API could ever do is let TikTok pick a song for us. Choosing a
specific song is a manual step in the TikTok app, permanently.

**The description field is larger than we use.** TikTok accepts 4000 characters
(`DESC_MAX` in `netlify/functions/lib/tiktok-payload.mjs` already reflects this); the
studio textarea caps at 2200.

## Design

### Constraint: the post title format is load-bearing

The post title stays exactly `{Movie} — movie trivia & behind-the-scenes facts`.

`parsePostedMovie()` in `netlify/functions/lib/queue.mjs` parses that shape to recover
which film a past post was about, which is how batch mode avoids proposing a film we
have already covered. Changing the title format silently breaks repeat-avoidance. Any
implementation that touches the title must keep `queue.test.mjs` green.

### 1. The agent writes the meta alongside the captions

The meta is generated by the same model call that writes the slide captions, in
`netlify/functions/lib/autopilot.mjs`. This is the only place where "do not repeat a
fact that appears on a slide" is enforceable rather than hopeful — the model has the
captions it just wrote in its own context.

`buildAutopilotPrompt()` takes a new `includeMeta` option. When set, the prompt asks
for one extra key beside `suggestions`:

```json
{
  "suggestions": [ ... ],
  "meta": {
    "hook": "John Carpenter's arctic paranoia classic, with Kurt Russell and Rob Bottin's practical creature effects.",
    "filmTags": ["thething", "johncarpenter", "80shorror"],
    "songs": [{ "title": "...", "artist": "...", "why": "..." }]
  }
}
```

Prompt rules for each field:

- **`hook`** — one or two sentences, at most 200 characters. Must name the film, its
  year, and at least two of: director, lead cast, genre/era, studio. **Must not state
  any fact used in a slide caption**, since the slides are the payoff. No hype words,
  no em dashes (same house rules the captions follow).
- **`filmTags`** — 2 to 4 lowercase tags specific to this film: the title, the
  director or a lead actor, and an era/genre/subject tag. No spaces, no `#`.
- **`songs`** — 0 to 3 notable songs from the film's actual soundtrack. Pop songs and
  needle-drops only, never the score. If the film has no notable licensed song, return
  an empty array rather than inventing one.

**This is additive and opt-in.** `normalizeSuggestions()` is not modified. A new
`normalizeMeta(raw)` reads `raw.meta` and returns `null` for anything malformed. The
`includeMeta` block only renders when a caller asks for it, so the single-slide
"write one more" path (`focusTimecode`, no title slide) sends a byte-identical prompt
to the one it sends today.

**Failure is non-fatal.** Missing, malformed, or empty `meta` falls back to today's
`defaultPostFields()` output. A bad meta must never cost us the captions. Per the
repo's logging rule, a dropped meta is `console.warn`ed with the model and a raw
preview, the way `tik-autopilot.mjs` already handles unusable suggestions.

### 2. Hashtags: 5 slots, 3 sources

New pure module `public/scripts/tik/hashtags.js`.

| Slots | Source | Example |
| --- | --- | --- |
| 1–3 | agent `filmTags` | `#thething` `#johncarpenter` `#80shorror` |
| 4–5 | house set, rotated | `#vhs` `#videostore` |

Five is the total, matching the 3–5 range that TikTok guidance converges on. Film tags
lead because they are where we can realistically rank; the house pair keeps us
categorized in the broad film-content buckets.

**House sets** are named pairs, rotated deterministically from the project id so a
given draft is stable across reopens while the account spreads across all five:

```js
export const HOUSE_SETS = [
  { key: 'trivia', tags: ['movietrivia', 'moviefacts'] },
  { key: 'filmtok', tags: ['filmtok', 'movietok'] },
  { key: 'retro',  tags: ['vhs', 'videostore'] },
  { key: 'bts',    tags: ['behindthescenes', 'filmmaking'] },
  { key: 'cult',   tags: ['cultclassic', 'movienight'] },
];
```

The chosen `key` is stored on the project as `hashtagSet`.

**Sanitizing is mandatory.** A model that returns `#The Thing (1982)` must not be able
to ship a broken tag. `sanitizeTags()` lowercases, strips everything outside `a-z0-9`,
drops empties and anything over 30 characters, dedupes case-insensitively, dedupes
against the house pair, and caps the result at 3.

Exports: `HOUSE_SETS`, `pickHouseSet(projectId)`, `sanitizeTags(list)`,
`buildHashtags({ filmTags, houseSet })`, `buildDescription({ hook, movie, hashtags })`.
Pure — no DOM, no network. Unit-tested at `test/tik/hashtags.test.mjs`.

### 3. The description

```
The Thing (1982), John Carpenter's arctic paranoia classic with Kurt Russell
and Rob Bottin's practical creature effects.
What's your favorite quote from the movie? Drop it in the comments.
Follow VHS Garage for more movie trivia.
#thething #johncarpenter #80shorror #vhs #videostore
```

Roughly 280 characters. Line one is the agent's `hook`; the remaining lines are
template, reusing the comment prompt and follow ask that already exist in
`defaultPostFields()`. Keywords ride in on the hook naturally rather than as a stuffed
block, and no slide's fact is spoiled.

The studio textarea `maxlength` goes from 2200 to 4000, matching what the API accepts.
`buildDescription()` produces far less than that; the cap exists so hand-editing is not
artificially constrained.

### 4. Song suggestions

Stored as `project.songs` — `[{ title, artist, why }]`. Rendered as a compact,
copy-ready list inside the existing "Post details" panel in `src/pages/tik.astro`,
next to the title and description fields, so the picks are in view while finishing the
draft. The panel is hidden when the array is empty.

These are never written into the description. They are a note to the human for a step
that happens in the TikTok app.

### 5. Measuring which tags work

New pure module `public/scripts/tik/tagreport.js`, rendered into the existing
`#stats-card` on the home screen, below the follower chart.

`summarizeHistory()` in `netlify/functions/lib/queue.mjs` gains a `tags` field, parsed
out of `video_description` — which `tik-history.mjs` already requests and currently
discards. Reading the tags off what actually shipped, rather than off our local project
records, means the report stays honest for hand-edited posts and for posts made from a
device whose library we no longer have.

The report groups posted trivia films two ways and shows, for each row, **n, median
views, and median engagement rate** (`(likes + comments + shares) / views`):

- by house set (which of the five pairs the post carried)
- by individual tag

Median rather than mean: one breakout post would otherwise drag an entire row.

**`n` is displayed on every row, always.** At ten posts per house set this is noise for
a long while, and a report that hides its sample size implies a confidence it has not
earned. The panel states plainly when the sample is too small to act on.

The report needs the `video.list` scope, which `tik-history.mjs` documents as possibly
ungranted (`scope: 'missing'`). That is an expected state, not an error: the panel
stays hidden and the existing hint is reused rather than showing a broken widget.

### 6. Existing drafts are left alone

Only newly written drafts get the new meta. Drafts already in the library keep whatever
copy they have. `makeProject()` gains `songs: []` and `hashtagSet: null`; records
written before this change simply lack the fields, and every reader treats absent as
empty. No migration is needed: IndexedDB stores whole records (`store.js`) and
`serializeProject()` in `app.js` spreads `...project`, so top-level fields persist
without being enumerated. (Slide-level fields are enumerated and would need adding by
hand — nothing in this design puts data on a slide.)

## Module boundaries

| Module | Responsibility | Pure? |
| --- | --- | --- |
| `lib/autopilot.mjs` | prompt for meta, validate the model's answer | yes |
| `tik/hashtags.js` | build a tag set and a description from meta | yes |
| `tik/tagreport.js` | parse tags from history, aggregate performance | yes |
| `lib/queue.mjs` | carry `tags` through `summarizeHistory()` | yes |
| `tik/app.js`, `tik.astro` | render songs and the report | no |

Each pure module is unit-tested under `test/tik/` alongside the existing suites, run by
`npm test`.

## Testing

- `hashtags.test.mjs` — sanitizing hostile agent output (spaces, punctuation, `#`,
  casing, over-long, duplicates); house rotation is deterministic per id and covers all
  five sets across ids; film tags never collide with the house pair; the assembled
  description shape.
- `tagreport.test.mjs` — parsing tags out of real description text; grouping; median
  with even and odd counts; engagement rate with a zero-view row; empty history.
- `autopilot.test.mjs` — `normalizeMeta()` on good input, missing `meta`, wrong types,
  over-long `hook`, too many tags/songs; and that `includeMeta: false` leaves the
  prompt byte-identical to today's.
- `queue.test.mjs` — `summarizeHistory()` still passes with descriptions that have no
  tags, and `parsePostedMovie()` is unaffected.

## Out of scope

- Changing the post title format (breaks `parsePostedMovie`).
- The `guys` and `year` formats — Tape Trivia only, per the request.
- Automatic hashtag selection based on the report. The report informs a human; it does
  not close the loop. Acting on n=10 automatically would be worse than not acting.
- Anything claiming to know TikTok-wide hashtag volume. We cannot see it.
